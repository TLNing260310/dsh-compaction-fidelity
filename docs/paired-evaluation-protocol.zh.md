# 三后端配对评测协议（待执行）

版本：1；日期：2026-10-06。本文定义验收方法，不包含真实评测结果。当前的 raw/final calibration 是同一次摘要在补偿前后的比较，不能替代三个后端的对照实验。

## 冻结环境与输入

比较官方 basic、compaction-pro、本插件。固定 Desktop 2.0.17 / Harness 0.2.0-rc.2、三个后端的准确版本/提交、模型与 provider 路由、模型参数、输入摘要区间、保留尾部、摘要输出上限、全局注入预算（injectionMaxTokens）、补偿预算、继续执行的工具权限和项目文件快照。每个后端使用独立 Profile 和工作区副本，清空校准历史，关闭可选宿主补丁。兼容性未通过的后端先报告安装失败，不能以删改配置后的不同预算冒充同条件结果。

先比较同一压缩区间的质量，再单独比较自动触发策略；否则早压缩与晚压缩的输入差异会混进质量结论。记录模型实际 tokenizer 的 token 和 provider usage；本插件的词法估算只作为辅助列。

保存冻结输入与项目快照的 SHA-256、后端/配置/模板版本、随机种子（如 API 支持）。中文、英文、中英混合按预先指定任务语言分层，本插件检测出的语言只能作为另一列，避免检测器替自己选择有利分组。失败、截断、取消和重试全部保留。

## 任务矩阵

每种语言至少 10 个独立任务，每任务重复 3 次：三个后端合计 270 次压缩及后续执行。可先做 3 个任务/语言的试运行来校验流程，但不能据此发布“同类领先”的结论。

| 任务族 | 关键事实与陷阱 | 后续验收 |
| --- | --- | --- |
| 定位与修复 | 相近的路径、大小写标识符、版本、精确错误串；在中段加入用户纠正 | 改到指定文件、修复指定失败、未修改禁止路径；用预先冻结的测试验收 |
| 数据与迁移 | 幂等性、备份位置、dry-run、禁止破坏原始证据；插入已撤销方案 | 重跑无副作用；最终采用最新授权；保留原始数据 |
| 架构续作 | 多模块依赖、过时文档与新决策、相似 scope；细节必须通过回查获得 | 回查正确来源并完成修改；记录失败回查、无依据断言与工具调用数 |

长输入采用真实的脱敏消息/工具事件，覆盖事实位于开头/中段/末尾、一次压缩/连续三次压缩、工具结果较长等条件。不要用重复一段噪声制造 350K 输入来代替真实长会话。冻结任务时同时冻结事实清单、允许动作、禁止动作及验收脚本，生成摘要后不得修改标准答案。

## 两轮比较与消融

第一轮只传入同一摘要区间，比较摘要和后续任务。第二轮给三个后端完整长会话，比较各自自动触发策略的总体成本与正确率。

本插件另做 compensation 开/关、anchors 开/关的消融。若某能力没有独立配置开关，可在独立实验分支中关闭该路径并记录 diff；不能用两个不同版本的插件来推断单个机制的收益。

## 评分与原始记录
